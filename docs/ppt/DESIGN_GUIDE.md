# 발표 자료 디자인 지침 — "사람이 만든 것처럼"

이 폴더의 HTML 발표 자료(`index.html`)가 따르는 규칙이다. 요즘 AI가 만든 슬라이드와 웹페이지에서 반복적으로 보이는 패턴(이하 "AI 티")을 조사해 피하고, 편집 디자인(신문·잡지·스위스 스타일 포스터)의 방법을 대신 쓴다.

## 1. 조사 요약 — AI 티로 꼽히는 것

여러 실무자 글이 공통으로 꼽은 패턴이다(측정 연구가 아니라 경험칙이다).

| 영역 | AI 티 |
| --- | --- |
| 색 | 보라·남색 그라디언트, 어두운 배경 위 시안, 글자에 그라디언트, 배경의 둥근 빛 번짐(radial glow), 반사적으로 고른 크림·베이지 배경 |
| 배치 | 가운데 정렬 표지, 똑같은 카드 3개(아이콘-제목-설명) 반복, 카드 안의 카드, 모든 간격이 같음, 의미 없는 장식 격자 배경 |
| 부품 | 카드 한쪽의 두꺼운 색 띠(왼쪽 액센트 바), 얇은 테두리+넓은 그림자 동시 사용, 유리 효과, 과하게 둥근 모서리, 알약 모양 배지 |
| 글자 | 제목 위에 제목을 반복하는 작은 대문자 라벨(eyebrow), 순서 없는 "01 02 03" 번호 라벨, 모든 곳에 같은 서체, 장식용 고정폭(mono) 대문자 |
| 문장 | 문장마다 대시(—), "X가 아니라 Y" 대구, 이모지 제목·불릿, "혁신적", "강력한" 같은 수식어, 둥근 숫자와 가짜 이름 |
| 움직임 | 모든 요소가 한꺼번에 페이드인, 의미 없는 깜빡임·맥박 점, 튕기는(elastic) 이징 |

원본 초안(`AI에게 역할을 주면 생기는 일`)에도 이 중 여럿이 있었다. 다크 배경의 빛 번짐, 마름모 장식이 붙은 대문자 라벨, 왼쪽 색 띠 카드, 🤔·🔍 이모지, 대시가 많은 문장이다.

## 2. 이 자료의 디자인 결정

무엇을 할지 미리 정해 두고, 그 안에서만 고른다. "기본값을 받아들이지 말고 결정하라"가 조사한 글들의 공통 처방이다.

### 2.1 판형과 격자
- 1920×1080 고정 판형을 화면 크기에 맞춰 통째로 확대·축소한다. 슬라이드 안의 배치가 화면마다 바뀌지 않는다.
- 12열 격자(여백 120px, 열 간격 32px)에 모든 요소를 맞춘다. 제목·본문·그림의 왼쪽 끝이 같은 선에 선다.
- **비대칭**이 기본이다. 텍스트는 왼쪽 5~6열, 그림은 오른쪽 6~7열처럼 무게를 나누고, 가운데 정렬 표지는 쓰지 않는다.
- 한 슬라이드에 **주인공 하나**(큰 제목, 숫자 하나, 그림 하나 중 하나)만 둔다.
- 관련 있는 것은 붙이고, 덩어리 사이는 크게 띄운다. 모든 간격을 같게 두지 않는다.

### 2.2 색
- 종이: 흰색에 가까운 회백(#F3F2EE). 크림·베이지는 피한다.
- 잉크: 거의 검정(#141414)과 회색 두 단계.
- **신호색 하나**: 주홍(#E5442B). 지금 말하는 대상, 다음 토큰, 선택된 경로처럼 "여기를 보라"는 곳에만 쓴다. 한 슬라이드에 한 군데가 원칙이다.
- 보조색 하나: 짙은 청록(#1F5C5A). 두 번째 모델·두 번째 에이전트처럼 비교 대상에만 쓴다.
- 그라디언트, 빛 번짐, 그림자, 유리 효과는 쓰지 않는다.
- 파트 구분 슬라이드만 색을 뒤집는다(잉크 바탕에 종이색 글자). 매 장 바뀌는 배경색으로 분위기를 내지 않는다.

### 2.3 글자
- 제목: 굵은 고딕(Gothic A1 800). 크게, 줄 간격은 좁게(1.08), 글자 사이는 기본값.
- 본문: IBM Plex Sans KR 400/500, 28~32px(1080 판형 기준), 줄 간격 1.5, 한 줄 30자 안팎.
- 숫자·코드·토큰: IBM Plex Mono. **실제 코드·토큰·수치에만** 쓴다. 장식용 대문자 라벨로 쓰지 않는다.
- 제목은 문장으로 쓴다. "~란?" 같은 주제어가 아니라 그 장의 결론을 쓴다(예: "다음 말 하나를 고르는 일을 반복한다").
- 굵기·크기·간격으로 위계를 만든다. 서체는 세 가지(제목·본문·고정폭)를 넘지 않는다.
- 쪽 번호는 오른쪽 아래 작게 한 번만. 제목 위 eyebrow 라벨은 두지 않는다. 대신 파트 이름을 왼쪽 위 여백에 작게 둔다(신문의 면 이름처럼).

### 2.4 그림
- 장식 아이콘, 이모지, 의미 없는 원·사각형 일러스트를 쓰지 않는다.
- 그림은 **설명하는 그림**만 그린다. 토큰이 하나씩 붙는 과정, 컨텍스트 윈도우가 차고 접히는 과정, 말이 wave를 따라 퍼지는 과정처럼 메커니즘을 보여 준다.
- 선은 1.5~2px의 잉크, 상자는 테두리만(채움 없음) 또는 면만(테두리 없음) 중 하나로 통일한다.
- 실제 화면 캡처는 **필요한 부분만 잘라** 확대하고, 가리키는 곳에 주홍 선 하나와 짧은 주석을 단다. 브라우저 틀(빨강·노랑·초록 점)은 그리지 않는다.

### 2.5 움직임(모션 그래픽)
- 움직임마다 한 문장으로 말할 수 있는 이유가 있어야 한다. 이유가 없으면 넣지 않는다.
- 슬라이드 전환은 **짧은 가로 밀기**(0.5초, ease-out) 하나로 통일한다. 매 장 다른 전환 효과를 쓰지 않는다.
- 슬라이드 안의 등장은 **읽는 순서대로 하나씩**(stagger 80~120ms). 제목 → 본문 → 그림. 모두 한꺼번에 나타나지 않게 한다.
- 메커니즘 그림은 **발표자가 넘길 때 한 단계씩**(→ 키) 진행한다. 말하는 속도와 그림이 맞는다.
- 이징은 `cubic-bezier(.2,.7,.2,1)`(빠르게 출발해 부드럽게 멈춤) 하나. 튕김·탄성 효과, 반복 깜빡임은 쓰지 않는다.
- 큰 요소는 조금 더 길게(0.6초), 작은 요소는 짧게(0.3초). 함께 움직이는 요소는 멈추는 시각을 조금씩 어긋나게 한다.
- `prefers-reduced-motion`이면 움직임 없이 최종 상태를 바로 보여 준다.

### 2.6 문장
- 대시(—)는 쓰지 않는다. 마침표로 끊는다.
- "X가 아니라 Y" 대구를 습관처럼 쓰지 않는다. 구분이 꼭 필요한 곳(LLM은 답을 찾지 않고 이어 쓴다)에만 한 번 쓴다.
- 수식어 대신 사실과 숫자. 실제 시나리오 이름, 실제 토큰 수처럼 구체적인 값을 쓴다.
- 한 장에 문장 셋을 넘기지 않는다. 나머지는 발표자 노트(N 키)로 보낸다.

## 3. 점검표 (슬라이드마다)

- [ ] 이 장의 주인공이 하나인가
- [ ] 제목이 결론 문장인가
- [ ] 주홍이 한 군데에만 있는가
- [ ] 모든 왼쪽 끝이 격자 선에 맞는가
- [ ] 이모지·그라디언트·그림자·대시·eyebrow 라벨이 없는가
- [ ] 움직임마다 이유가 있고, 읽는 순서대로 나오는가

## 4. 조작법 (index.html)

| 키 | 동작 |
| --- | --- |
| → / Space / 클릭 | 다음 단계(그림 단계 → 다음 장) |
| ← | 이전 |
| Home / End | 처음 / 끝 |
| N | 발표자 노트 보기 |
| F | 전체 화면 |
| G | 격자 보기(정렬 점검용) |

주소 뒤 `#7`처럼 쪽 번호를 붙이면 그 장에서 시작한다.
